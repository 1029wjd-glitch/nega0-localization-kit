# 한국어 로케일 종료 사례: 존재하는 파일을 검색하지 못함

## 관찰과 수정 단계

한국어 시스템 로케일에서 설치·한글패치 후 초반 회상/디버깅 장면이 조용히 종료됐다. 직접 실행, Locale Emulator 실행, 원본 복원에서도 같은 지점이 보고됐다. 설치 화면의 일부 문자가 깨졌다는 사실만으로 게임 파일 손상을 단정하지 않았다. 실제 ef.arc/besg.arc 원본 해시는 기존 원본 해시 기록과 일치했다.

문자 판별 수정판은 CP932 데이터에 시스템 ACP의 IsDBCSLeadByte를 쓰던 문제를 수정했다. CP949와 CP932는 256개의 byte 값 중 66개의 lead-byte 판정이 다르다. 이 수정은 필요했지만 사용자는 **동일 장면에서 재종료**를 보고했다. 따라서 인코딩 수정만으로 해결됐다고 결론내릴 수 없었다.

## 원본 아카이브 정렬과 검색 로케일

MIKO의 NDIX 파일명 목록은 일본어 비교 순서로 저장돼 있다. 엔진은 이 목록에 이진 검색을 사용하면서 `CompareStringW(LOCALE_SYSTEM_DEFAULT, NORM_IGNORECASE, ...)`를 호출한다. 한국어 시스템 로케일에서는 목록의 정렬 조건과 비교 조건이 달라진다. 선형 검색으로는 존재하는 이름이 이진 검색에서 누락될 수 있다.

문제 텍스처는 `丸影.png`였다. ef.arc에서는 index 54, besg.arc에서는 index 15180에 존재하지만 한국어 비교 검색에서는 -1이 나왔다. 실제 Windows API를 사용해 원본의 모든 이름을 검색한 과거 결과:

| 아카이브 | 이름 수 | 일본어 비교 실패 | 한국어 비교 실패 |
|---|---:|---:|---:|
| Data/ef.arc | 188 | 0 | 4 |
| Data/besg.arc | 15,181 | 0 | 311 |
| 합계 | 15,369 | 0 | 315 |

원본으로 동일 현상을 재현하는 읽기 전용 도구:

```powershell
python repack/verify_archive_locale.py "D:\Games\Nega 0\Data\ef.arc" "D:\Games\Nega 0\Data\besg.arc"
```

현재 시스템 기본값 결과는 실행 환경에 따라 달라진다. 일본어·한국어 LCID는 명시적으로 각각 검사한다. Python의 기본 문자열 정렬이나 locale 모사로 이 결과를 대체하지 않는다. 다른 판본의 수량은 다를 수 있다.

## 좁게 적용한 파일명 정렬 수정판 수정

SHA-256으로 확인된 1.0.1.0 EXE, ImageBase `0x400000` 기준 VA `0x4170ed`의 push immediate만 `0x800` → `0x411`로 바꾼다. 바로 다음 `0x4170f2`는 CompareStringW IAT 호출이다.

```text
원본 11 bytes: 68 00 08 00 00 FF 15 3C 31 67 00
수정 11 bytes: 68 11 04 00 00 FF 15 3C 31 67 00
```

VA를 파일 offset으로 착각하지 않는다. `pefile.get_offset_from_rva(va - ImageBase)`로 바꾸고 원본 명령 signature도 검사한다. 동적으로 만들어 정렬하는 다른 컨테이너의 CompareStringW 호출 9곳은 그대로 둔다. 시스템 로케일 자체를 변경하지 않는다. 일본어 시스템에서는 이 비교의 의미가 기존과 같을 것으로 예상하지만, 양쪽 환경의 실제 플레이 통과를 대신하는 증거는 아니다.

## 크래시 경로와 확신의 한계

진단 연결은 원래 ESO 함수의 인자·반환값·cdecl을 유지하면서 이름/index/count를 기록한다. 로그에서 텍스처 index -1이 관찰됐다. 코드의 `0x5eb9b0` 범위 검사는 잘못된 index에 NULL을 반환하며, 호출부는 이를 확인하지 않고 `0x5eb600`으로 전달한다. 그 함수의 `0x5eb61d`에 있는 `mov eax,[edi+3c]`는 Windows에 남은 접근 위반 주소(RVA `0x1eb61d`, `0xc0000005`)와 일치한다.

이는 로그, 검색 재현, 코드 경로를 결합한 강한 원인 근거다. 실시간 충돌 레지스터/스택 덤프는 확보하지 않았다. **2026-10-05 사용자가 파일명 정렬 수정 후 실제 문제 장면을 이상 없이 통과했다고 확인했다.** 문서를 읽는 AI는 자동 검색 검증 통과와 게임 플레이 통과를 구분해 보고해야 한다.

런타임 로그는 기본 `%TEMP%\Nega0Korean-runtime.log`, 선택 환경변수 `NEGA0_KOREAN_LOG`로 경로 지정 가능하다. 로컬 UTF-8 기록이며 대략 1MiB에서 추가 기록을 제한한다. 공개 이슈에 원본 대사·개인 경로가 포함된 전체 로그를 그대로 올리지 말고 필요한 부분을 검토해 사용한다.
